# Data
## Which sources, and why

Everything comes from  [Yahoo Finance](https://finance.yahoo.com/),
via the [`yfinance`](https://github.com/ranaroussi/yfinance) library, pulled by
[`trader/data/collector.py`](../trader/data/collector.py).

Yahoo was chosen because it is free and returns dividend and split-adjusted
prices directly (`auto_adjust=True`). Convenience does pose some problems, which are listed below. 

- Historical prices can be changed later because of things like stock splits (NVIDIA split into 10 for example). So if we download the data again, we might get different results. 
- There is no delisted stocks data, this introduces survivorship bias
- There are rate limits

The files themselves live under [`data/`](../data), split into
[`raw/`](../data/raw) and [`derived/`](../data/derived) - see
[Layout](#layout) below.

## How much data
| | |
|---|---|
| Rows | 802,455 |
| Tickers | 276 in the price file, 275 in the ticker list |
| Date range | 2014-02-18 → 2026-02-18 |
| History per ticker | 3,019 trading days for most, 570 for the shortest |
| Format | long / tidy — one row per (Date, Ticker) |
| Live file | `data/raw/prices/esgu_ohlcv_daily.csv`, 227MB |

This is daily data from the last 12 years. This is a time span long enough so that the model can learn and such that names on this list trade publicly long enough. 

### Our data has survivorship bias

The ticker list is today's ESGU constituents, applied to twelve years of
history. Anything that was in the index in 2014 and subsequently went bankrupt,
got acquired, or was dropped for ESG reasons is absent.

This inflates results, and it does so in exactly the direction that flatters a
long-only strategy. We do not correct this bias so it stands as a limitation and an assumption that is worth holding in mind. 

## What the data looks like

We use daily OHLCV bars: Open, High, Low, Close, Volume, plus `Adj Close`.

- Adjusted Close (`Adj Close`) takes stock splits into account by retroactively adjusting historical prices to reflect the split

It is useful to note that our raw price series are non-stationary, which means that their mean and variance drift over time. 

- We want to predict with stationary estimators
-  Therefore our engineered features are usually differences, ratios, and normalizations which are stationary
-  This ensures that patterns we learn from the past are still useful for the future
